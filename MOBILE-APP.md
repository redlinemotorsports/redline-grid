# Redline Grid Mobile

The mobile app is a separate, mobile-first experience packaged with Capacitor. The existing root `index.html` website remains the desktop/web experience and is not replaced by this app.

## Stack

- Vanilla HTML, CSS and JavaScript
- Capacitor 8
- Android and iOS native shells
- A Node build script that copies `mobile/` into Capacitor's `www/` web directory and bundles the 2026 season archive

## Requirements

- Node.js 22 or newer
- Android Studio and Android SDK for Android builds
- macOS with Xcode for iOS builds

## First-time setup

```sh
npm install
npm run build
npx cap add android
npx cap add ios
npx cap sync
```

The Android platform can be built on supported Windows, macOS or Linux development machines. The iOS platform requires macOS and Xcode.

## Development

Edit the mobile app in `mobile/`. The current build copies `archive/2026.json` into `www/data/2026.json`, which powers the home snapshot, upcoming race schedule, latest classification and championship tables.

Then run:

```sh
npm run build
npx cap sync
```

Open the native project:

```sh
npx cap open android
npx cap open ios
```

Or use the convenience scripts `npm run open:android` and `npm run open:ios`.

## Architecture rules

- Keep the existing desktop dashboard in the repository root unchanged.
- Keep mobile UI and mobile-specific assets inside `mobile/`.
- Reuse data endpoints and business logic only through deliberate shared modules/adapters; do not copy the entire desktop DOM into the app.
- Do not ship mock race results, fabricated session status or invented schedule data.
- Keep API credentials out of the app bundle.
- Native platform folders are generated by Capacitor and should be committed after the first successful platform setup.

## Current milestone

The mobile shell has five primary destinations: Home, Schedule, Live, Results and More. Home, Schedule and Results now read the real 2026 archive: the next Grand Prix and session timetable, latest completed race podium/classification, and driver/constructor standings. Session times are formatted in the device's local timezone. Live timing remains an honest between-session state until a supported live data source is integrated.

Next: connect a supported live timing source, complete the secondary More destinations, then generate and test the Android/iOS native projects on their required toolchains.
